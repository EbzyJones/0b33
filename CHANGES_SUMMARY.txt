MULTI-SIG PROPOSAL INVALIDATION SECURITY FIX - CHANGES SUMMARY
===============================================================================

ISSUE:
  After admin rotation, stale guardian votes can execute privileged operations
  without new admin consent, violating multi-sig authorization model.

ACCEPTANCE CRITERIA:
  1. On admin rotation, invalidate all pending multi-sig proposals
  2. On guardian removal, re-evaluate quorum for all pending proposals

HOW THE FIX WORKS
===============================================================================

SCENARIO: Stale Guardian Vote After Removal
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
t=0:    Setup: Alice (60%), Bob (40%), total=100, need 67% quorum
t=100:  Proposal P1 created
t=110:  Alice votes YES (60 votes, need 67)
t=200:  Alice is removed
t=300:  try_execute(P1):
        - calculate_quorum() reads current guardians: only Bob (40%)
        - Looks for Alice's vote in proposal
        - Alice not in guardian set → weight lookup returns None
        - Alice's vote excluded (counts as 0)
        - votes_for = 0, total_weight = 40
        - quorum = 67% of 40 = 27
        - Check: 0 < 27 → EXECUTION FAILS ✓

SCENARIO: Admin Rotation
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
t=200:  Admin rotated to NewAdmin
        → invalidate_pending_proposals() called
        → Sets cutoff to current_proposal_id
t=210:  try_execute(old_proposal):
        → ensure_proposal_not_invalidated() checks: proposal_id < cutoff
        → Returns ProposalInvalidated error ✓
